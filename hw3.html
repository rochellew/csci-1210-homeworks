HW3: Personal Gallery Page

CSCI-1210 Fall 2026

Build a small 2-page-deep website: one gallery page with four images, each linking to its own info page.

Based on the cohort's suggestion, this assignment is more open-ended than previous ones. You'll make the choices about topic, wording, and images -- the instructions below tell you what the site needs to do, not exactly what to type.

1. Download the starter code

Download the starter code (hw3.zip) off D2L and unzip it -- this gives you the project folder you'll build everything in for the rest of these steps.

2. Pick a topic

Choose four things you want to make a page about -- favorite characters, foods, hobbies, places you want to visit, whatever interests you. You'll build one gallery page linking to four individual info pages, one per item.

3. What you're given

Your project folder already contains a starter template:

  • hw3.html -- the gallery page. Has a 2×2 grid with 4 placeholder image/link/caption blocks already wired up.
  • page-template.html -- a blank info page. You'll duplicate this file 4 times, once per item.
  • style.css -- some starter CSS, already linked from every page. You don't need to touch this (we haven't covered CSS yet!), but feel free to look at it.
  • images/ -- put your optimized images here.

4. Find and optimize your images

Find one image for each of your four items. Remember what we covered on image optimization --resize/compress them before adding them to the project so the page loads quickly. Save all four into the images/ folder.

Tip — portrait vs. landscape images: Don't worry if your four images are different shapes (some tall, some wide). style.css already includes a rule that makes all gallery images display at the same size and shape, so your grid will look even no matter what you pick. If you want more control over which part of the photo shows, you can crop it yourself in GIMP first (see below) — but it's not required.

Optimizing images in GIMP

Two settings do most of the work of shrinking a photo down to something web-friendly:

  1. Resize it. Image → Scale Image. Photos straight off a phone or camera are usually way bigger than they need to be on a webpage. Set the width to something reasonable, e.g. 800px wide, and GIMP will scale the height to match. This is the single biggest factor in file size.
  2. Set Quality on export. File → Export As…, choose .jpg, and click Export. A dialog pops up with a Quality slider (0–100). Somewhere around 75–85 usually looks nearly identical to the original but is a fraction of the file size — drag it down and watch the "Preview" file size estimate in the dialog shrink.

Optional: if you'd rather crop instead of relying on the CSS above, use the Crop Tool (Shift+C) before exporting.

5. Build the gallery page (hw3.html)

For each of the 4 grid items, update:

  • The <img> src -- point it at your image in images/
  • The <img> alt text -- describe the image
  • The caption <p> text below the image
  • The <a href="..."> -- this should point to the info page you'll create for that item (see step 6)

Also update the page <title> and the heading/intro text in the header.

6. Build your four info pages

Duplicate page-template.html four times. Rename each copy to match one of the href values you set in step 5 -- for example, if a gallery link points to denmark.html, your duplicated file should be named denmark.html.

In each info page, update:

  • The <title> and <h1>
  • The <img> src and alt (can reuse the same image or use a different one)
  • The paragraph -- a few sentences about that item
  • On one of the four pages: a list (see the requirement below)

Leave the "← Back to gallery" link as-is -- it should already point back to hw3.html.

Requirement — include a list:

At least one of your four info pages needs to include a list -- an ordered list (<ol>), an unordered list (<ul>), or a definition list (<dl>). Use whichever fits that item naturally (steps, ingredients, specs, related terms, etc.) -- you only need it on one page, not all four.

page-template.html has a commented-out example you can uncomment and edit.

Note — relative paths: Every src and href in this project (images/your-image-1.jpg, page1.html, etc.) is a relative path — it points to another file based on where the current file lives, not a full web address. That's why hw3.html can find images/your-image-1.jpg: it looks for an images folder right next to itself. This only keeps working if you preserve the same folder structure everywhere you put this project — on your computer, and later when you upload it. If images/ ends up in the wrong place relative to your HTML files (or doesn't get uploaded at all), your images and links will break even though the code itself is correct.

7. Test it

Open hw3.html in your browser. Click each of the 4 images and confirm it takes you to the right info page, and that the "Back to gallery" link on each info page brings you back.

About the tools you're using

Including Bootstrap

You don't need npm, Node, or any install step. The template already includes Bootstrap the simple way -- a <link> tag in the <head> pointing at a CDN (a copy of thefile hosted on a public server):

<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" rel="stylesheet">

That's it -- as long as this tag is in a page's <head>, you can use any Bootstrap class in that page.

Bootstrap classes used in the template
Class What it does
container Adds sensible margins/padding around content
row / col-6 Lay elements out side-by-side in a grid (two col-6s per row = 2 columns)
img-fluid Makes an image resize to fit its container
rounded Rounds the corners of an element
text-center Centers text/inline content
mt-2, mb-4, py-3, py-4 Margin/padding utilities (t=top, b=bottom, y=top+bottom); number = spacing amount
d-block Forces an element to display as a block (needed so mx-auto below can center it)
mx-auto Centers a block-level element horizontally
w-50 Sets an element's width to 50% of its container

Feel free to use any other Bootstrap utility class too.

What the heck's a <div>?

You'll notice the grid in hw3.html uses <div> tags. We haven't formally covered <div> yet -- for now, just know it's a generic container with no meaning of its own, used to group other elements together (here, so Bootstrap's grid classes have something to attach to).

You don't need to add any new <div>s for this assignment, just edit the content inside the ones already there.

If you're curious, read more here: w3schools: The div element.

Uploading your files (FileZilla → csci1210.com)

Make sure that your work is uploaded to the right place. Your URL should look like the following:

http://USERNAME.www.csci1210.com/homework/hw3/hw3.html

Replace 'USERNAME' with your lowercase ETSU username. If the link doesn't take me to your page, I can't grade it.

Once everything works locally, upload your whole project folder to the class server:

  1. Connect to the server in FileZilla using your course credentials.
  2. Navigate to /homework/ on the remote (right-hand) side.
  3. Either create a folder called hw3 on the remote side OR name your folder on your device hw3 that contains your files and upload the whole folder.
  4. Upload hw3.html, page-template.html (or rather, your four renamed info pages), style.css, and the entire images/ folder — keep the same folder structure you have locally (see the relative paths note above). Don't upload page-template.html itself if you've already renamed your copies of it.
  5. Visit your page at the corresponding csci1210.com URL and click through it exactly like you did locally to verify that everything works.
Warning — check the server, not just your computer: A page that works when you double-click hw3.html on your own machine can still break once uploaded, usually because of a relative path issue (see the note above) or a missing file. Always do your final check by visiting the live csci1210.com URL, not just your local file.
